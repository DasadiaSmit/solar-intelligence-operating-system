# Security and access model

## Configuration

- Credentials and provider keys are runtime environment variables only.
- `.env.local` is ignored; `.env.example` contains names and safe defaults only.
- API responses, health output, provenance, logs, and client props must never contain secrets.
- External provider hosts are selected from trusted configuration, not arbitrary request URLs.

## Identity and roles

The hosted application can use dispatcher-provided ChatGPT/workspace identity headers through `app/chatgpt-auth.ts`. Sample read-only operation remains anonymous-compatible.

Authentication establishes identity, not workspace membership. Authorization is repeated server-side on every write. The domain role model is:

- `viewer`: read sample/public scientific results;
- `researcher`: create and modify owned sites, scenarios, annotations, and experiments;
- `operator`: manage operational site records and ingestion jobs within an authorized scope;
- `admin`: manage role assignments and read audit records.

Until a role record is provisioned, authenticated users receive the minimum researcher-owned scope; no client-supplied user or role field is trusted.

## API controls

- Versioned routes validate latitude, longitude, date range, array bounds, battery bounds, and maximum workload.
- Invalid input returns a stable 4xx error without provider access.
- Upstream calls use timeouts, abort signals, retry allowlists, and maximum attempts.
- Rate limiting is applied before expensive simulation or provider work.
- Reanalysis cannot satisfy a request that explicitly requires an issued forecast.
- Cache keys are derived from canonical validated requests.
- CORS remains same-origin unless a specific deployment has an approved origin list.

## Persistence

- Every user-owned query is scoped by authenticated identity/tenant.
- D1 receives metadata and bounded JSON, not arbitrary large payloads.
- R2 snapshot keys are content-addressed and immutable.
- Audit events append actor, action, resource, timestamp, request/result IDs, and a redacted change summary.
- SQL is issued through Drizzle or prepared statements; request text is never interpolated into SQL.

## Browser security

The Worker adds conservative content-type, referrer, frame, and permissions headers. A production Content Security Policy should be tested against the exact Vinext build before enforcement; it must not be copied from an unrelated Next deployment. Download/export filenames are generated by the application and content types are explicit.

## Dependency and supply-chain security

- Production, development and build dependencies are locked and installed with `pnpm install --frozen-lockfile`.
- `pnpm run security:audit` checks the complete lockfile and blocks unexcepted high or critical advisories independently of the deterministic offline test suite.
- Direct dependencies are exact-pinned unless an existing repository policy deliberately uses a constrained range.
- Transitive overrides must be parent-scoped, justified by a public advisory, and verified against native loading, peer dependencies, strict TypeScript, lint, tests and the exact Vinext/Cloudflare production build.
- A temporary exception may ignore only one exact GHSA identifier. It must be recorded in `governance/security-exceptions.json` with reachability, compensating controls, owner, remediation gate and expiry. The governance suite fails after expiry.
- Registry availability and advisory-database freshness remain external dependencies. A passing audit proves only that the consulted database reported no unexcepted high/critical finding for the resolved lockfile at that time.

## Incident response

Provider-key exposure requires immediate rotation and log review. Incorrect scientific output requires preserving the original lineage, marking affected result IDs superseded, issuing a new calculation version, and communicating the impacted time range/assumptions. Deleting the evidence is not an acceptable correction.
