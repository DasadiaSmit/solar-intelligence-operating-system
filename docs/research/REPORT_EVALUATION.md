# Report information evaluation (study 03)

The frozen protocol is `assessment-protocol-03.json`, committed at `a57740c` before benchmark outputs. This is a deterministic software information evaluation, not a human usability study or a new photovoltaic simulation.

Six complete, hand-defined arithmetic cases provide 48 question opportunities per condition. A point estimate is compared with equal-information tables and the existing evidence report. The literal answers were independently recomputed without the project comparator. The report formatter remains byte-identical to commit `0dde63d2643514127e4383bfd6da9e69f91a03b4` for the primary run.

Two incomplete-input cases and one deliberately corrupted cached-choice renderer case are reported separately. They must not be included in the complete-case denominator or treated as normal operating failure rates. The previously inspected Sheffield result is a transfer/reproduction example, not a fresh validation set.

## Reproduction

Use a clean committed checkout and the pinned project Node dependencies. With Node on PATH:

```sh
node --import tsx scripts/research/run-report-benchmark.mts STUDY01_ANALYSIS_DIRECTORY NEW_PRIMARY_INPUT_DIRECTORY
python scripts/research/evaluate-reports.py NEW_PRIMARY_INPUT_DIRECTORY NEW_PRIMARY_RESULTS_DIRECTORY
```

Python plotting/rendering uses the already installed research runtime (Python 3.12.14, matplotlib 3.10.7 and Markdown 3.9). Set `PYTHONDONTWRITEBYTECODE=1` to avoid generated bytecode inside the source checkout.

The generator verifies the study 01 source manifest, disables network fetches and preserves report Markdown. The evaluator verifies the benchmark manifest, observes displayed Markdown only, and records its extraction evidence. It does not import the production comparison function or use hidden objects as displayed evidence. New output directories are required; existing results are never replaced.

## Fair comparison and boundaries

The table condition receives the same underlying nominal, historical and omission values as the evidence condition. It displays the full raw historical matrix; the existing report displays computed regrets and reversal summaries instead. “Equal-information” refers to question-answerability from shared inputs, not identical displayed fields. Direct labelled lookup is explicit; calculating minima, maxima, regret or sacrifice is derivable. An incorrect explicit assertion cannot be rescued by correct arithmetic elsewhere. Missing information and a rejected generation are recorded separately from false claims.

The benchmark measures information availability and correctness under fixed templates. It cannot establish faster reading, better decisions, financial value, statistical significance or generalisation to unseen cases. Its fixtures were designed with knowledge of the software. A later guard or report improvement must preserve the primary outputs and be evaluated as an exploratory same-case rerun, not independent validation.

The three fixture stress cases do not test every possible malformed input. In particular, missing whole scenarios and nonfinite numeric values are outside the frozen fixture coverage.

## Exploratory revision after preserved primary results

The primary implementation/evaluator was frozen at `83687bf35bb34c16efdb95de74a00e0cb4f145ff`. It produced 42 explicit and 6 additional derivable answers for the original evidence report, 12 and 36 for raw tables, and 18 explicit with 30 omitted for point summaries. The six complete cases contain no wrong explicit answers. Separate stress cases showed a rejected incomplete matrix, an invalid infinite omission range and a cached-choice conflict.

The separately versioned `decision-evidence-report-2.0.0` recomputes decisions from raw values, shows nominal sacrifice explicitly and retains supported facts in a partial report. It does not change the original report or any physics calculation. Its API requires named expected scenarios, provenance and explicit null markers for missing cells. Malformed dimensions, duplicated scenario identities and invalid numeric data are rejected rather than substituted.

Run its same-case regression only after preserving the primary input and result folders:

```sh
node --import tsx scripts/research/run-report-exploration.mts PRIMARY_INPUT_DIRECTORY STUDY01_ANALYSIS_DIRECTORY NEW_EXPLORATORY_INPUT_DIRECTORY
python scripts/research/evaluate-report-exploration.py NEW_EXPLORATORY_INPUT_DIRECTORY PRIMARY_RESULTS_DIRECTORY NEW_EXPLORATORY_RESULTS_DIRECTORY
```

The exploratory wrapper imports the unchanged primary extraction rules. It verifies the primary manifests, copied report bytes, and all 216 original fact records before adding the new condition. It does not alter the frozen protocol or turn reused fixtures into independent validation. A revised Sheffield report is included as an unscored transfer example.

The primary SVG has nondeterministic creation metadata and element identifiers; its numerical outputs, Markdown, HTML and PNG replay exactly. The exploratory wrapper fixes SVG identifier seeding and removes its date for reproducible figure bytes. No scoring logic is changed.
